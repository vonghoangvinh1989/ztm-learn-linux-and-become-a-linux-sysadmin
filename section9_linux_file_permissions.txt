1) Understanding the file permissions
    Each file assigned to 3 different categories of users:
    - file owner
    - group owner
    - others

    3 file permissions types: read (r), write (w), execute (x)

    ls -l /etc/passwd --> view the file '/etc/passwd' permission
        -rw-r--r-- 1 root root 2965 Sep 20 19:08 /etc/passwd

        -: means this is file
        rw-: owner permission
        r--: group permission
        r--: other permission

    ls -l users.txt --> owner has read and write permission, so he/she can modify a file 
        -rw-rw-r-- 1 vonghoangvinh vonghoangvinh 240 Sep 20 20:44 users.txt

    chmod u-r users.txt --> remove read permission of file users.txt 
        --w-rw-r-- 1 vonghoangvinh vonghoangvinh 240 Sep 20 20:44 users.txt
    cat users.txt --> will show error permission denied
    id > users.txt --> still work since 'users.txt' still has the write permission 

    chmod u-w users.txt --> now remove the write permission for 'users.txt'
    ls -l users.txt --> check permission of users.txt now, there is no permission
        ----rw-r-- 1 vonghoangvinh vonghoangvinh 145 Sep 20 20:47 users.txt
    ifconfig > users.txt --> permission denied since it lost the write permission

Note: read and write permissions does not apply to 'root', even 'root' does not have
these permissions, 'root' still can view and modify the file (so only non-privilegde users get affected)

2) Octal (numeric) notation of file permission
    a) command to view
        stat /etc/passwd --> another way to view permisison on linux file (octal and also have symbolic)
            Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)

    b) octal notation
        For example:
            0755 = 755
            0644 = 644

            r(read) = 4
            w(write) = 2
            x(execute) = 1
            - (no permssions) = 0

            rwx = 4 + 2 + 1 = 7
            rw- = 4 + 2 + 0 = 6
            r-- = 4 + 0 + 0 = 4

            for example:
                rw-rw-r-- = 664
                rwxr---wx = 743
                rwxr-xr-- = 754

3) Changing File Permissions (chmod)
    a) 'chmod' command 
        Command 'chmod' is used to change file permission and only root or file owner can
    change the file permission
        Syntax: chmod [who] [operation] [permissions] filename

        who: signify the user category whose permissions will be changed
            u: user
            g: group
            o: other

        operation: flag define whether permissions are to be removed, added or set 
            -: remove
            +: add 
            =: change the current permissions to the specified Permissions

        permissions: specify using letters 'r', 'w' or 'x'

    b) how to use
        chmod u-w user.txt --> remove write permission of owner on file user.txt
        chmod u+rwx user.txt --> add 'read, write, execute' permission of owner of file user.txt 
        chmod -v u-x,g+w,o-rwx user.txt --> remove 'execute' on user, add 'write' on group 
    and remove 'read, write and execute' on group of user.txt, can -v to see more details with verbose
        chmod ug-r,u+x,o-rwx user.txt --> remove 'read' of owner and group, owner add 'execute', and remove
    'read, write and execute' of other 
        chmod a+r,a-wx user.txt --> 'a' stand for all, all add 'read' and all remove 'write' and 'execute'

        chmod ug=rw,o= user.txt --> instead of using '+' and '-', we can assign permission 
    using '=', here user and group will have read and write, other will have no permission

        chmod 644 user.txt --> using numeric to add permission
        chmod 777 user.txt --> giving full permission for all categories
        chmod 400 user.txt --> only 'read' permission for owner, other categories have no permissions
        
        ls -lR ./dir1 --> list permission and display recursively all files and folders in dir1
        chmod -R 750 dir1/ --> change permission to 750 to all files and folders inside dir1

        chmod --reference=i.txt user.txt --> make permission of 'user' is the same of 'i.txt' by
    using 'i.txt' reference option 

4) The effect of permissions on directories
    a) set 'read' permisson on directory
        chmod 400 linux/ --> set 'read' permission for directory 'linux'
        ls -ld linux/ --> view permission of 'linux' directory 
            dr-------- 3 vonghoangvinh vonghoangvinh 4096 Sep 23 18:20 linux

            'read' permission in directory mean: directory's contents only showed
        by 'ls', it does not give access to content of directory (could not remove the
        file inside the directory or cd into that directory)

        ls -l linux --> try to read the contet of directory, but only show ????
            total 0
            d????????? ? ? ? ?            ? ubuntu
            -????????? ? ? ? ?            ? users.txt

    but when I tried

        mv linux/ l --> change the name of 'linux' into 'l' successfully, why? because the parent
    of linux have permission 'rwx' to do that, changing directory name actually
    works at level of parent (rename directory entry not 'linux' directory)

    b) read and write permission on directory
        chmod 600 linux/ --> add read and write permission for owner of 'linux' directory 
        cd linux/ --> permission denied 
        rm linux/users --> permission denied
        touch linux/a.txt --> permission denied 

        Note: 
            Add the 'write' permission does not change much if the 'execute' permission 
        does not set. But if we set both 'write' and 'execute', that means we can modify the 
        directory content
            Write permission has effect only along with execute permission
            Execute permission on directory: mean access to directory content

    c) read, write and execute permission on directory
        chmod 700 linux/ --> add full permission for 'owner' of linux, can do anything
    as above, (create, delete file, cd into directory, ls, ls -l, cat, etc)
        chmod 000 linux/a.txt --> set no permission for file inside, what happen
    if we try to delete 'a.txt', we free to do so since directory has the permission 

        Note: permission on parent directory was more important than the permission on file

    d) other notes 
        ls -l linux/ --> list inside of 'linux'
        ls -ld linux/ --> list that 'linux', self directory

        File permissions → control what you can do with the CONTENT of a file.
        Directory permissions → control what you can do with the ENTRIES inside the directory.
        Renaming/deleting an entry → permissions are primarily checked on the PARENT directory.

5) Combining Find and Chmod Commands Together 
    When we change permissions recursively on path, we should exclude directory because sometimes we can 
mistakenly make the directory useless such as directory only has 'read' and 'write' permission. And now
how can we cd into that directory and read the content?
    Solution: combine 'find' and 'chmod'

    find ~ -type f -exec chmod 640 {} \; --> find all files in ~ and 
set permissions to 640
    find ~ -type d -exec chmod 750 {} \; --> find all directories in ~ and
set permissions to 750

6) Changing File Ownership (chown, chgrp)
    Only root can change the file owner 

    a) changing owner of file 
        sudo chown toor cpu.txt --> change owner of 'cpu.txt' into 'toor'
            -rw-rw-r-- 1 toor vonghoangvinh 2883 Sep 25 19:43 cpu.txt

    b) changing owner of multiple files at the same time
        sudo chown toor cpu.txt interfaces.txt i.txt linux/ --> change owner of multiple files
and directories
    
    c) changing owner of the file using 'user id' or uid instead of username
        sudo chown +1001 cpu.txt --> instead of changing using username, we can use the user id 
but add the + before the id to specify the parameter will be number user id

    d) changing owner and group at the same time using 'chown' and ':'
        sudo chown vonghoangvinh:daemon cpu.txt --> we can change the owner and group
at the same time by separating it by ':' or colon (some allow to write like this: sudo chown vonghoangvinh.daemon cpu.txt)

    e) changing group of file 
        sudo chgrp sudo cpu.txt --> change the group of file 'cpu.txt' into 'sudo'

    f) changing group of file using 'chown'
        sudo chown :sudo cpu.txt --> change the group of file 'cpu.txt' into 'sudo'
by using chown command with colon (:)

    g) changing group and owner at the same time and recursively, should app to directories have files inside
        sudo chown -R vonghoangvinh:vonghoangvinh ~ --> changing recursively directories
and everything inside, we can use -R: recursively, changing both group and owner

7) Understanding SUID (set user id)
    + Temporarily treat normal user as root or another user, that when set user id comes into primarily
    + Executable file with suid executed, the resulting process will have the permissions of owner of the file command, not
the permissions of the user who executes the command

    a) set suid bit and why 
        cat /etc/shadow
            cat: /etc/shadow: Permission denied

        sudo chmod 4755 /usr/bin/cat --> add 'set user id' to /usr/bin/cat, 4 means 'set user id'
        
        ls -l /usr/lib/cargo/bin/coreutils/cat
            -rwsr-xr-x 115 root root 11352352 Apr 16 06:41 /usr/lib/cargo/bin/coreutils/cat --> see the 'rws', s mean set user id bit
    was set

    b) remove 'execute' permission will see the capital S
        sudo chmod u-x /usr/bin/cat --> remove 'execute' permission on this file 
        
        ls -l /usr/lib/cargo/bin/coreutils/cat
            -rwSr-xr-x 115 root root 11352352 Apr 16 06:41 /usr/lib/cargo/bin/coreutils/cat --> see the capital 'S',
    when we see the 'S' that mean that file lost the 'execute' permission 

    c) view the permission suit bit with stat command
        stat /usr/lib/cargo/bin/coreutils/cat --> we can view the suid bit by using 'stat'
    command, 4775, 4 mean suid bit or small 's' in '-rws' 
            File: /usr/lib/cargo/bin/coreutils/cat
            size: 11352352  	Blocks: 22176      IO Block: 4096   regular file
            Device: 8,2	Inode: 1969385     Links: 115
            Access: (4755/-rwsr-xr-x)  Uid: (    0/    root)   Gid: (    0/    root)
            Access: 2026-09-25 20:31:04.669499486 -0600
            Modify: 2026-04-16 06:41:19.000000000 -0600
            Change: 2026-09-25 20:31:03.932485441 -0600
            Birth: 2026-07-03 22:38:29.617182479 -0600

    d) set uid bit using symbolic mode
        sudo chmod u+s /usr/bin/cat --> set suid bit using symbolic, now cat will have 
the permission of its owner which is root no matter who is execute it
        cat /etc/shadow --> can view the content of this file (before will be permission denied)

    e) remove suid bit using symbolic mode
        sudo chmod u-s /usr/bin/cat --> remove suid bit to make secure again (avoid bad habit or behavior or misuse)
        cat /etc/shadow --> permission will be denied

    f) find all file has at least suid bit set
        find /usr/bin/ -perm -4000 -ls --> find all files have at least these Permissions

8) Understanding SGID (Set Group ID)

    + set SGID on directories, all files or directories created inside will be owned by the same
group owner of the directory where SGID was configured 
    + useful in 'shared' directories, or directories that are writable at the group level

9) Understanding the sticky bit
    + Sticky bit apply to directories
    + Sticky bit allows to create a directory that everyone can use as a shared
file storage. The files are protected because no one can delete anyone's else files

    chmod 1777 /temp/ --> setting sticky bit on directory '/temp/', purpose is not allow
anyone can delete file of anyone's else, normally even user set 600 on files inside of 'temp',
other users can still delete it because parent directory '/temp' allow permmissions on it
    chmod o+t /temp --> using symbolic mode to set sticky bit
    ls -ld /temp/ --> check sticky bit was set on that, see 't' on 'rwt'
        drwxrwxrwt 2 root root 4096 Sep 26 19:45 /temp/

    Note:
        SUID → file → "run as owner"
        SGID → directory → "inherit group"
        Sticky → directory → "protect deletion"
        Other directories have sticky bit set is: /var/tmp and /tmp

10) Umask allows to view and set the default permissions on files and directories in linux
    0666 for files --> full permissions for files
    0777 for directories --> full permissions for directories
    
    a) view umask and understand 
        umask --> show '0002' mean current permissions is 0777 - 0002 = 0775 for directories,
    and 0666 - 0002 = 0664 for files

    b) now we would like to have newly created file has permission 0644, how can we set
umask. Now do the calculation: 0666 - 0644 = 0022, the value '0022' will be set for umask
        umask 0022 --> the default permissions for files and directories

        Create new file and directory, we will have 644 for files and 755 for directory

11) Understanding Files Attributes (lsattr, chattr)
    Some useful attributes:
        a: append
        A: no access time updates
        i: immutable - no modifed, no deleted, no renamed

    a) view file attributes withs 'lsattr'
    lsattr --> view file system attributes of files or directories in Linux
        --------------e------- --> extends

    b) add file attributes with 'chattr'
        + append 
            sudo chattr +a user.txt --> add attribute 'append' or 'a' in file user.txt 
            lsattr user.txt --> view file attribute 'user.txt'
                -----a--------e------- user.txt
            ls > user.txt --> now we can not modify the content of the file
                bash: user.txt: Operation not permitted
            sudo ls > user.txt --> not even root can do that
                bash: user.txt: Operation not permitted
            ls >> user.txt --> but we can append to the file successfully

        + no access time update
            chattr +A user.txt --> add attribute 'no access time updates' with A
            lsattr user.txt --> view file attributes
                -----a-A------e------- user.txt
            stat user.txt --> check atime and saw it was not updated since it was set 'A'

        + immutable: can not be modified, can not be deleted, can not be renamed, can not create hardlink
            sudo chattr +i i.txt --> add attribute 'immutable' for file 'i.txt'
            
            sudo rm -rf i.txt --> operation not permitted 
            sudo ls > i.txt --> operation not permitted
            sudo ls >> i.txt --> operation not permitted
            sudo chmod 700 i.txt --> operation not permitted 

            sudo chattr -R +i dir1/ --> add attribute 'immutable' recursively
            lsattr -R dir1 --> view attributes recursively

    c) remove attribute
        sudo chattr -R -i dir1/ --> remove attribute -i recursively
        sudo chattr -i i.txt --> remove attribute -i for file i.txt
