1) Task automation and scheduling using cron (crontab)
    a) Understanding of cron
    There are two types of cron jobs: system wide and individual user 
        ls /var/spool/cron/crontabs/ --> files to store users' scheduled cron jobs
        which crontab --> command to manage cron jobs is crontab 
        ls -l /etc/crontab --> system wide crontab configure file 

    crontab -l --> list all cron jobs of current user 
    crontab -e --> using editor to edit current user's crontab file to create, modify or
remove scheduled cron jobs
        Note: 
            + m h dom mon dow command --> minute, hour (24 hour: 0 - 23), date of the month, month, 
                date of the week(0 - 7: 0,7 is Sunday, 1 is Monday, 6: Saturday) and command 
            + if we put the "*" for the specific field, it mean always or any value for that field
                * in the day or week mean: every day or every week 

        + for example: we want to run a script to do backup everyday at 6am 
            0 6 * * * /root/backup.sh --> '/root/backup.sh' is the bash script 

        + for example: we want to run a script to monitor free disk every minute
            * * * * * /root/check_space.sh --> every minute
        
        + for example: run a task at 4, 6 and 10 am 
            0 4,6,10 * * * /root/check_space  --> run at 4, 6 and 10

        + for example: run a task on weekdays between 9 and 5pm, once per hour using range
            0 9-17 * * 1-5 /root/firewall.sh --> this mean run 1 time at 9, 1 time at 10 to 17 from monday to friday 

        + for example: run a task at 4:10 and 21:10 every 3 days of the month
            10 4,21 */3 * * /root/task.sh --> using / operator to specify values that will be repeated over a certain interval 

        @yearly /root/happy_new_year.sh --> run the task once a year on the 1st of January at midnight 
            or 0 0 1 1 *
        
        @monthly /root/task.sh --> run the task once a month at midnight on the 1st day of month
            or 0 0 1 * * 
        
        @weekly /root/task.sh --> run the task once a week at midnight on Sunday 
            or 0 0 * * 0

        @daily /root/task.sh --> run the task once a day at midnight 
            or 0 0 * * * 

        @hourly /root/task.sh --> run the task once a hour at the beginning of hour 
            or 0 * * * *

        @reboot /root/task.sh --> run the specify task at boot time 

    b) practical example 
        */2 * * * * date >> /tmp/date_and_time.txt --> output date into file '/tmp/date_and_time.txt'
    every two minutes

        tail -f /var/log/syslog --> cron log file in ubuntu
        cat /tmp/date_and_time.txt --> view content of date_and_time.txt 

        crontab -r --> remove all cron jobs for current user

    c) root user can edit, create and remove cron jobs for other users
        sudo su --> become root 
        crontab -e -u vonghoangvinh --> edit cron job for user 'vonghoangvinh'
            * */5 * * * apt update 

        crontab -r -u vonghoangvinh --> delete cron tab of user 'vonghoangvinh'

    d) root user can restrict which user can use the crontab command using these two files
/etc/cron.allow, /etc/cron.deny

    e) system-wide cron job, we can move our scripts into these folders
        + /etc/cron.daily/
        + /etc/cron.hourly/
        + /etc/cron.monthly/
        + /etc/cron.weekly/

        less /etc/crontab --> will specify exactly when cron job will be running

        Note: use the absolute path for 'crontab'

2) Scheduling Tasks Using Anacron (anacron)
    a) Understanding Anacron
        cat /etc/anacrontab --> the file which specifies the anacron jobs is /etc/anacrontab 
        sudo vim /etc/anacrontab --> view file with root privileges
            7   10 cron.weekly  run-parts --report /etc/cron.weekly

            Explanation: run-parts is the command runs all executable files found in the directory,
                all executables or scripts found in /etc/cron.weekly be executed with a frequency of 7 days
                
                7 (first field): it specifies the frequency of the job, expressed in days (1: every day, 7: every 7 days or weekly)
                    we can specify: '@daily, @weekly, @monthly' at this field
                
                10 (second field): delays in minutes, how long anacron will wait before executing the job 
                
                cron.weekly (third field): job identifer, should be unique and is the name of a file that will be created 
                    at /var/spool/anacron. This is called the job timestamp file, will contain a single line that indicates
                    'the last time this job was executed'
                        
                        sudo cat cron.weekly
                            20261016

                run-parts --report /etc/cron.weekly (fourth field): command that will be executed 
            
            For example:
                2 1 backup date >> /tmp/anacron.txt
            
    b) Anacron commands
        anacron -T --> check syntax error with -T for anacron testing
            
        sudo anacron -d --> run anacron job at debug mode, will run jobs that never run before 

        sudo anacron -d --> run again, no jobs will be run since all be executed 

3) Mounting and Unmounting File System
    a) view file system with mount command and type
        mount -l -t ext4 --> list filesystem was mount with type ext4 (-l: list, -t: type)
        mount -l -t vfat --> list filesystem was mount with type vfat 

    b) view char device
        ls -l /dev/sdb --> this is char device file that represent usb stick 
            brw-rw---- 1 root disk 8, 16 Oct 24 21:36 /dev/sdb
    
    c) find usb devices or partitions
        sudo fdisk -l --> to find the name of the device file, we can use command fdisk with option -l for listing 
        
        lsblk --> command to list all block devices 

    d) mount and umount devices
        sudo mount /dev/sdb1 /home/vonghoangvinh/Desktop/usb/ --> mount usb device into folder 'usb'

        sudo mount -t ext4 /dev/sdb1 /home/vonghoangvinh/Desktop/usb/ --> mount the save at above but 
with option '-t' ext4 to specify file system 

        sudo umount /home/vonghoangvinh/Desktop/usb --> unmount the mount point, only unmount when the 
partition is not used 

        sudo umount -l /home/vonghoangvinh/Desktop/usb --> option '-l' mean 'lazy', it means unmount the 
partition when it is not busy or not used 

        sudo mount -o ro /dev/sdb1 /home/vonghoangvinh/Desktop/usb/ --> mount with other options using 
option '-o' and ro here means 'read only'

        sudo mount -o rw,remount /dev/sdb1 /home/vonghoangvinh/Desktop/usb/ --> remount the above with 'read write'

        sudo mount /path_to_iso_file /home/vonghoangvinh/iso -o loop --> mount an iso file

4) Working with device files (dd: command to convert and copy a file)
    sudo su --> change to root privileges

    dd if=/dev/sdb of=/home/vonghoangvinh/backup-usb.img status=progress --> backup device '/dev/sdb'
into backup-usb.img file, (if: input file, of: output file), dd working with block, not data, it will copy everything 

    dd if=/home/vonghoangvinh/backup-usb.img of=/dev/sdb status=progress --> restore from 
the image file 

    dd if=/home/vonghoangvinh/backup-usb.img of=/dev/sdb status=progress conv=sync --> short block will
be added to have 512 bytes per block

    dd if=/dev/sda2 of=/dev/sdb status=progress --> backup partition to /dev/sdb 

    dd if=/dev/sda2 of=/root/mbr.dat bs=512 count=1 --> copy 512 bytes of partition /dev/sda2
into file /root/mbr.dat, bs=512 means one block read/write has the size of 512 bytes, count=1 means
just handle one block, backup of master boot record 

    dd if=/root/mbr.dat of=/dev/sda2 bs=512 count=1 --> restore the mbr from the file mbr.dat
in case of problem 

    dd if=/home/vonghoangvinh/Downloads/kali-linux.iso of=/dev/sdb bs=4M status=progress --> make 
bootable usb disk 

5) Getting System Hardware Information
    a) Get hardware info
        sudo su --> become root 

        lshw --> extract detailed info of hardware configuration of machine 

        lshw | less --> pipe to less to view

        lshw -json | less --> output with 'json' format
        
        lshw -html > hw.html --> output with 'html' format and write to file hw.html 

        lshw -short --> view brief info of hardware

        inxi -Fx --> alternative command to show hardware information

    b) Get CPU info
        lscpu --> display info about cpu and its architecture 
        lshw -C cpu --> display info about cpu but in another format 

        lscpu | grep -i mhz --> we can use filter to get the info we need, 'here is mhz'
        lscpu -J --> output with json format about cpu

    c) Get memory info
        dmidecode -t memory --> get info about memory 
        dmidecode -t memory | grep -i size --> search only for size of memory 
        dmidecode -t memory | grep -i max --> find the maximum capacity for memory 

        free -m --> check the capacity of memory used or free 

    d) Get pci ports info
        lspci --> list all the pci buses and detailed about the devices connect to them 

        lspci | grep -i wireless --> get info about wireless card 
        lspci | grep -i vga --> get info about vga

    e) Get usb ports info
        lsusb --> get info about usb ports 
        lsusb -v --> print out detailed info about each usb port with option -v: verbose 

    f) Get hard drive info
        lshw -C disk --> get info about hard drive with lshw 
        lshw -C disk -short --> get the short version of above

        lsblk --> get info of all block devices, including hard disks and partitions

        fdisk -l --> get more info about hard drive such as file system type, number of sectors, etc
        fdisk -l /dev/sda --> get info of '/dev/sda'

        hdparm -i /dev/sda --> get/set of sata drive
        hdparm -I /dev/sda --> get identification info directly of sata drive with more detail

        hdparm -t --direct /dev/sda --> test the hard drive and get benchmark
            --direct: bypass the page cache
            -t: perform timing 

    g) Get info about wireless device 
        iw list --> show info about wireless device 
        iw list | less 

    h) Most of the commands so far get info from /proc
        cat /proc/cpuinfo --> get info of cpu 
        cat /proc/meminfo --> get info of memory
        cat /proc/partitions --> get info of disk partitions 
        cat /proc/version --> see the version of running kernel

    i) Get version of running kernel 
        uname -r --> get info of running kernel with -r: kernel release 
        uname -a --> get all info of running kernel 

    j) Get info of battery 
        acpi -bi --> get battery info include capacity and charge status 
        acpi -V --> get all info
