1) Getting information about the network interfaces (ifconfig, ip a)
    a) Using ifconfig
        ifconfig -a --> display list of all network interfaces and ip address, both
    enabled and disabled (lo: loopback interface, enp0s3: ethernet interface (en), port 0 (p0) slot 3 (s3) )

        ifconfig --> display list of network and ip but only enabled

        ifconfig enp0s3 --> display info of the specific interface, here is 'enp0s3'

    b) Using ip a
        ip address show --> display list of all network interfaces and ip address, 
can write (ip addr show / ip a show / ip a)

        ip -4 address --> show only ip ver 4

        ip -6 address --> show only ip ver 6

        ip addr show dev enp0s3 --> show info of specific interface 'enp0s3'

    c) view default gateway
        route --> view default gateway, UG (G) mean gateway at 'Flags'
        route -n --> use number instead of symbolic host name

        ip route show --> the same but use ip command

    d) view dns server
        resolvectl status --> can view dns server ip address

2) Configuring the network on the fly
    a) Up and down network interface using ifconfig command
        ifconfig enp0s3 down --> make the interface down and it's not displayed by the 'ifconfig'
command 

        ifconfig -a --> display them by using -a option to show all

        ifconfig enp0s3 up --> up the network interface, can see the interface 'running'

    b) Up and down network interface using ip command
        ip link set enp0s3 down --> set the network interface down using 'ip' command (watch 'STATE down') 

        ip link show dev enp0s3 --> show the interface enp0s3

        ip link set enp0s3 up --> set the network interface up using 'ip' command, we can see the 
status now 'STATE up'

    c) setting ip address using ifconfig command
        ifconfig enp0s3 192.168.0.111/24 up --> set the ip address for interface enp0s3,
remember it will not be permanently, reset and it will be gone

    d) setting ip address using ip command 
        ip address del 192.168.0.111/24 dev enp0s3 --> remove the ip address '192.168.0.111/24'
by using command 'ip'

        ip address add 192.168.0.111/24 dev enp0s3 --> add the ip address '192.168.0.111/24'
by using command 'ip'

    e) setting default gateway
        route del default gw 172.16.1.254 --> delete the default gateway

        route add default gw 172.16.1.254 --> add the default gateway

    f) setting default gateway using ip command
        ip route del default --> delete the default gateway using 'ip' command 

        ip route add default via 172.16.1.254 --> add the default gateway using 'ip' command 

    g) setting mac address using ifconfig command
        ifconfig enp0s3 down --> down the network interface 

        ifconfig enp0s3 hw ether 08:00:27:51:05:09 --> change mac address of network interface 

        ifconfig enp0se up --> up the network interface

    h) setting mac address using ip command
        ip link set dev enp0s3 address 08:00:27:51:05:01 --> set mac address using 'ip' command 

        ip link show dev enp0s3 --> show network interface 

    i) setting secondary ip address 
       sudo ifconfig enp0s3:10 10.0.0.10/24 up 

3) Setting Up static ip on Ubuntu (netplan)
    ls /etc/netplan --> contain the file to configure network with netplan
    sudo su --> becoming root before settings

    systemctl stop NetworkManager --> stop NetworkManager before configurating
    systemctl disable NetworkManager --> disable NetworkManager so it won't start after system restart
    systemctl status NetworkManager --> check the status of NetworkManager

    systemctl is-enabled NetworkManager --> check NetworkManager start when restart or not
        disabled 

    vim /etc/netplan/01-netconfig.yaml --> create new yaml file to configure network
        network:
            version: 2
            renderer: networkd
            ethernets:
                enp0s3:
                dhcp4: false
                addresses:
                    - 172.16.1.93/24 --> ip we want to have 
                gateway4: "172.16.1.254"
                nameservers:
                    addresses:
                    - "8.8.8.8"
                    - "8.8.4.4"

    netplan apply --> apply the changes
    
    ifconfig --> to see the new ip address
    route -n --> to see the default gateway

4) Testing and Troubleshooting Network Connectivity
    a) ping command
        ping ubuntu.com --> ping the domain 'ubuntu.com' continuously

        ping ubuntu.com -n --> ping but avoid doing 'reverse dns lookup'

        ping -c 4 ubuntu.com --> ping but only sent 4 packets with option '-c'

        ping -i 0.4 -c 5 google.com --> normally ping sent each packet each second, but we can change
    that with option '-i', here is set '0.4' second 

        sudo ping -q -c 5 google.com --> only showing the 'summary' after ping 

        ping -t 1 -c 3 -n ubuntu.com --> ping with ttl is '1' to see what is the first router toward
    'ubuntu.com'

    b) how to troubleshooting network 
        route -n --> check the default gateway

        ping 172.16.1.254 --> ping the default gateway, if can not ping, then we have problem
    in our LAN 

        ping 8.8.8.8 --> ping public dns server such as google or (1.1.1.1), if can not ping,
    problem with internet 

        ping google.com --> ping internet domain, if it's not working, then we could have 
    dns issue

    Client side

        sudo ufw app list --> list all current application profile 
        sudo ufw allow ssh --> allow connect ssh to server machine via firewall

    Client side
        ssh -v vonghoangvinh@172.16.1.93 --> connect to server with verbose option, show more info (-Vv)

    Server side
        sudo tail -f /var/log/auth.log --> check the server log 

7) Securing the OpenSSH Server 
    ls /etc/ssh/sshd_config --> configure ssh file for daemon (server)
    ls /etc/ssh/ssh_config --> configure ssh file for client 

    sudo vim /etc/ssh/sshd_config --> open file configure with vim 
        Port 2278 --> change port 22 to random port (before #Port 22)
        PermitRootLogin no --> not allow root direct login into ssh
        AllowUsers vonghoangvinh --> specify which users are allowed to ssh
        ClientAliveInterval 300 --> set the interval to 300 seconds, the ssh server sends a message 
    to check whether the client is still responsive
        ClientAliveCountMax 0 --> never disconnect the client because of unanswered checks  

Suppose we only permit 2 ips from network to allow to connect ssh 
    sudo su --> becoming root 
    iptables -A INPUT -p tcp --dport 2278 -s 'first ip address permit' -j ACCEPT
    iptables -A INPUT -p tcp --dport 2278 -s 'second ip address permit' -j ACCEPT
    iptables -A INPUT -p tcp --dport 2278 -j DROP 

8) Copying Files Over the Network
    a) Trouble shooting ssh connection before running scp command
        sudo ufw status verbose --> check status current status firewall
        sudo ufw allow 2278/tcp --> set firewall allow port 2278, because we already set
    the ssh will listen on port 2278 on server before 

        sudo systemctl restart ssh --> restart ssh
        sudo systemctl restart ssh.socket --> restart ssh.socket
        sudo systemctl status ssh --> check ssh status 
        sudo systemctl status ssh.socket --> check ssh.socket status 

        sudo ss -tlnp | grep ssh --> check ssh server is currently listening on which port

        Still not working?
        sudo sshd -t --> test ssh server configuration for errors
        sudo systemctl daemon-reload --> reload systemd unit configuration file
        sudo systemctl restart ssh.socket --> restart ssh socket unit
    b) Running SCP command
        + From client to server 
            scp -P 22 ip.txt vonghoangvinh@172.16.1.93:~ --> copy file 'ip.txt' from client side to server - 172.16.1.93
        with user 'vonghoangvinh' at home directory 

            scp -P 22 ip.txt vonghoangvinh@172.16.1.93:~/ip_ubuntu_client.txt --> same like above
        but this time change the filename into 'ip_ubuntu_client.txt'

            scp -r -P 22 mydir1/ vonghoangvinh@172.16.1.93:~ --> copy the directory mydir1 to 
        home directory in server (remember option -r with recursively)

            scp -rp -P 22 mydir1/ vonghoangvinh@172.16.1.93:~ --> same but with option -p: lowercase p will
        preserve modification time, access time from the source file 

        + From server to client
            scp vonghoangvinh@172.16.1.93:/etc/passwd /home/vonghoangvinh --> copy file '/etc/passwd' from
        server to client side (: is how scp differentiate between server and client)

            scp -r vonghoangvinh@172.16.1.93:~/Desktop /home/vonghoangvinh/TestingDesktop --> copy folder 'Desktop'
        from server to client side into /home/vonghoangvinh/TestingDesktop

        + From remote to remote
            scp user@IP1:/path_to_source_file user2@IP2:/path_to_destination_dir --> copy file between
        two remote machine, prompting will ask the password of two users

9) Synchronizing Files and Directories using rsync
    a) Trailing slash in rsync '/'
        if type '/etc' --> rsync will copy directory 'etc' itself to the destination 
        if type '/etc/' --> rsync will copy only the content of 'etc' to the destination

    b) Using rsync to do the backup
        sudo rsync -av /etc/ ~/etc-backup/ --> this rsync command can use to backup file and directories, -a: archive mode,
    keep everything of the sources (permissions, etc)

        sudo rsync -av /etc/ ~/etc-backup/ --> run this command again, rsync will do nothing, why? 
    rysnc find files that need to be transferred using a quick check algorithm that look for files
    that have changed in size or in last modified time, more efficient than the 'cp' command 

        sudo rsync -aq /etc/ ~/etc-backup/ --> using '-q' quiet mode option, do not print anything instead of -v print everything

        sudo rsync -av --delete /etc/ ~/etc-backup/ --> mirroring between source and destination, anything was not existed
    in source (/etc) will be deleted in ~/etc-backup/ with --delete option 

    c) Exclude files and directories when copying using rsync
        sudo vim exclude_files.txt
            movie1.mkv
            dir1/
            *.png

        rsync -av --exclude-from='./exclude_files.txt' my_project/ backup/ --> backup content of 'my_project'
    and exclude files and directory specified in 'exclude_files.txt'

        rsync -av --exclude='*.png' my_project/ backup/ --> we can use '--exclude' option to specify the path_to_destination_dir
    of files we would like to exclude 

        rsync -av --exclude="*.png" --exclude='a.pdf' my_project/ backup/ --> we want to exclude multiple files,
    using multipe --exclude options

12) Checking for listening port 
    a) Using netstat command 
        sudo netstat -tupan --> u: udp port, p: proces id and the name of program we listening, a: all ports both listening
    and not listening, n: shows numerical addresses
            local address: 0.0.0.0 mean process is listening on all ip addresses of the host
        
        sudo netstat -tupan | grep :22 --> check port 22 is open or ssh
        sudo netstat -tupan | grep :80 --> if no output, that means port 80 is not open 
        sudo netstat -tupan | gres sshd --> filter 'sshd'

    b) Using ss command
        ss -tupan --> same like above netstat

        lsof --> list open files, check which files are opened and which process is using them

        sudo lsof -u vonghoangvinh --> list open files of user 'vonghoangvinh'

        sudo lsof -u ^root --> list all open files not by 'root' (use negate by ^)

        sudo lsof -c nginx --> list all files opened by process 'nginx'

        sudo lsof -iTCP -sTCP:LISTEN --> list all TCP ports that are in LISTEN state and 
    identify which processes are listening on them
            -iTCP: display network resources associated with TCP
            -sTCP:LISTEN filter the results to show only TCP socket in the LISTEN state

        sudo lsof -iTCP -sTCP:LISTEN -nP --> see both ports and hostname in numeric format
            -n: Displays numeric IP addresses instead of attempting hostname resolution.
            -P: Displays numeric port numbers instead of service names such as ssh or http.

        sudo lsof -iTCP:22 -sTCP:LISTEN -nP --> check which file is using open port 22, here 
    systemd and sshd both listen on port '22'
